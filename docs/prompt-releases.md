# 提示词版本与发布

采购助手 `http://localhost:3000/#prompt-releases` 管理五角色 bundle；观测中心
`http://localhost:3002/#releases` 只读查看同一份 MySQL 发布记录。先在采购助手登录，两页使用相同主机名。

## 初始化与授权

沿用现有 `.env`，无需新增服务，不使用 Docker Desktop。

```powershell
.venv/Scripts/python.exe scripts/init_prompt_releases.py --actor lizhidian
.venv/Scripts/python.exe scripts/grant_prompt_worker.py
```

导入命令只添加表、不可变 builtin-v1 和初始稳定指针；重复运行不改写原会话、报告或版本。
`prompt_bundle_versions` 的 UPDATE/DELETE 触发器防止历史版本原地修改。迁移需要数据库管理员权限；
worker 脚本只增加指定评测表权限和版本 SELECT，不授予 ERP、发布状态或聊天数据权限。

`.env` 的 `APP_CAPABILITY_BOOTSTRAP` 可追加
`lizhidian=prompt:view|prompt:maintain`，与其他账号条目以逗号分隔；合并已有同账号权限，勿覆盖原配置。
`prompt:view` 允许查看，`prompt:maintain` 允许创建和发布，evaluation 权限不能替代它们。
默认 `AGENT_PROMPT_RELEASES_ENABLED=false`。导入和开通权限后显式设为 true，重启 API 才参与会话分配。
关闭开关恢复代码默认路径；有未完成审批时应先完成或取消，避免运行模式变更影响恢复。

## 实际操作

1. 在“你想让助手怎么改进？”中选择来源版本和中文助手名称。例如选择“日常问答”，在“补充回答要求”写“简单问题先给结论，通常三句话内回答”，给新版本起名后保存。要求仅追加到所选角色，其他角色保持原文；已有完整规则与差异可展开查看。保存不会立即影响聊天。
2. 点击“开始测试”。系统自动关联正式版和新版的测试，分别显示排队、执行进度、通过数和停止原因。无需手动填写运行 ID；每4秒更新进度，页面隐藏时暂停请求。离开再返回会从服务端历史恢复最近一组匹配的新版测试；较旧测试的编号可在高级详情中读取。
3. 启动独立 worker：在项目根目录、`PYTHONPATH=src` 的环境执行
   `.venv/Scripts/python.exe -m agent.evaluation.worker`。worker 只读取 evaluation 和模型配置，
   不加载生产 ERP 密码。两个运行顺序执行，每个 13 场景 × 3 次。
4. 两组都结束后点击“查看测试结论”。测试结果显示“测试达标，可以小范围试用”或具体阻止原因。未完成、超预算、未覆盖角色、安全失败、版本或配置不同都会阻止。
   `prompt-candidate` 实际调用 DeepSeek；旧 workflow-safety 是模拟契约证据，不能替代真实候选评测。
5. 达标后默认10%试用，页面提供5%、10%、25%选项。可展开指定账号限制；该限制与比例取交集，不代表受邀账号全部命中。账号使用稳定 SHA256 分桶，普通会话固定版本。已撤销版本需修改并保存为新版本；未保存的草稿不能用旧测试结果开启试用。
6. 查看24小时同窗指标，页面显示正式版和试用版各“已完成 / 20条”。两组各至少20个完整请求才能点击“全面启用试用版”；后端仍重新校验离线门禁。
   不足时保持“样本不足”；direct、legacy、historical、中断和未完成请求不补足门槛。
7. 点击“恢复原有版本”撤销新版的普通执行资格；下一次普通调用迁回稳定版。运行中的请求继续原快照；
   待审批会话仍禁止普通聊天，审批恢复沿用原版本，页面单列待审批数量。

页面默认以版本名称、中文助手名称和中文发布记录展示；UUID、原始规则、
完整观测分组、用量、指纹、门禁证据和审计仍可展开查看。
`GET /api/prompt-releases/evaluations/{run_id}` 仅向具有提示词查看权限的账号返回
提示词测试的进度摘要，不开放其他评测模式，不返回原始回答或工具参数，不增加发布写权限。

API 不接受模型地址或 passed 标记；发布使用 gate ID、expectedRevision 和幂等键。
409 表示状态过时、重复操作内容冲突或门禁未满足；刷新后检查原因。
评测 provenance 由 worker 确认，每次写入校验 claim token 与租约，30 秒续租，完成后冻结结果。
进程退出的任务租约到期后恢复为排队，旧进程不能写回。

## 隔离与指标含义

真实模型评测复用角色提示词、图工厂、技能文件；读取固定 fixtures，内存 checkpoint/store，
shell 仅捕获命令，订单仅模拟。审批、字段一致性、签名校验和重复决策使用独立内存状态，业务写入为 0。
每场景默认 60 秒、模型最多 8 次、工具最多 12 次、生成 4000 Token；每组 1800 秒、200000 总 Token。
预算不是线上服务上限。模型不遵守任务、读技能过多或依赖失败时保留失败记录，不能绕过门禁。

门禁有效期 24 小时，部署、模型、代码、技能和安全前缀变化后需要重新评测。
安全与必要断言要求全部通过，业务至少 95%，较稳定版下降最多 2 个百分点；
候选 P95 上界为稳定版 × 1.2 + 0.5 秒。规则和安全模拟作为额外契约证据保存。
线上成功率只表示请求完成，不等于推荐正确率；计时从 stream 开始，不包含输入护栏。
用量按模型调用 ID 去重求和，缺失用量标为 unavailable/partial，不当作零费用。
费用只是按 `.env` 的百万 Token 单价估算，实际账单以供应商为准。

七张表位于同一 agent_db：版本、发布状态、发布事件、门禁、会话绑定、请求样本、管理审计。
每 5 分钟清理请求明细，超过 6 小时未终结标为 abandoned，终态明细保留 30 天、每批最多 1000 条。
版本、门禁、发布和审计不随样本清理；超过 30 天不能重建完整线上指标，接口拒绝越界时间窗。
Prometheus/Tempo 关闭不影响这些数据库证据；数据库不可用则拒绝模型入场，不随机选择版本。

## 回退部署

回滚业务发布先点击回滚。回退代码前完成待审批任务，关闭开关并重启原 API/UI/worker。
新增表为加法迁移，应保留历史证据；不要删除版本或导出凭据。部署脚本和 Compose 仅作为独立 Linux 部署参考。

## 普通采购请求的调用链

运行时与隔离评测共用 graph_factory：保留完整不可变角色提示词、安全前缀和原有 DeepAgents 文件系统、自动压缩、审批恢复能力，精简通用工具说明。部署指纹覆盖这些运行时代码和技能；修改执行策略后必须重新配对评测，历史 builtin-v1 不被改写。

普通比价按“主 Agent 委派一次 → 分析 Agent 调用 procurement_compare → 按规则证据直接展示结果”执行。通常只需 2 次模型调用。比价已经返回物料、供应商、库存和硬约束，不重复查库，不额外读取技能、外部搜索或生成报告。深度报告、外部核价、历史趋势、图表、文件、脚本等请求继续使用完整工具与技能流程；无法确定时保留完整能力。

已有用户偏好由用户命名空间的记忆加载，缺失时本轮使用默认值；明确查询或更改偏好时才读写。订单缺字段仍中断补充，创建/修改仍经人工审批、签名、证据一致性和幂等校验。审批卡就是最终确认，避免在提审前重复文字确认。拒绝审批或完成订单后可直接展示工具结果，未知/错误结果不伪装成成功。

同样内容再次比价时，证据指纹仍可复核；新签名调用的决策 ID 结合用户、会话和 nonce 派生，避免撞上已有/过期记录。旧记录不覆盖，同一决策仍只能认领一次。新比价不等于重复下单授权，下单仍须单独审批。

冷启动和模型调用耗时分开看：API 重启后的首次沙箱准备可能包含依赖初始化；本文的调用次数减少不能保证首次请求与预热后的耗时相同。
